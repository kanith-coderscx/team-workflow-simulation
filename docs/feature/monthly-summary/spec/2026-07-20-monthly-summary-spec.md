# Spec: สรุปยอดรายเดือน แยกตามหมวดหมู่ (monthly-summary)

- **slug:** `monthly-summary`
- **priority:** p2
- **วันที่:** 2026-07-20
- **ผู้เขียน:** BA/SA

## สรุปงาน (Summary)

หน้าสรุปยอดของเดือนที่เลือก โดยอ่านข้อมูลจาก `localStorage` คีย์ `tws.transactions` ผู้ใช้เลือกเดือนได้ (เดือน/ปี) ระบบคำนวณและแสดง ยอดรายรับรวม, ยอดรายจ่ายรวม, ยอดคงเหลือ (รายรับรวม − รายจ่ายรวม) และรายละเอียดแยกตามหมวดหมู่ของเดือนนั้น ช่วยให้ผู้ใช้เห็นภาพการเงินรายเดือนได้เร็ว

## หมายเหตุ/ขอบเขต (Scope notes)

- อ่านข้อมูลจาก schema เดียวกับที่ `add-transaction` เขียน (คีย์ `tws.transactions`) — เป็นหน้าอ่านอย่างเดียว (read-only) ไม่แก้/ไม่ลบข้อมูล
- การกรองเดือนใช้ปี-เดือนจาก field `date` (`YYYY-MM`) — รายการที่ `date` อยู่ในเดือนที่เลือกเท่านั้นที่ถูกนับ
- ค่าเริ่มต้นของตัวเลือกเดือน = เดือนปัจจุบัน
- ยอดคงเหลือคำนวณจาก "รายรับรวม − รายจ่ายรวม" ของเดือนนั้น (อาจติดลบได้ ต้องแสดงเครื่องหมายลบให้ชัด)
- การแยกตามหมวดหมู่: แสดงยอดรวมต่อหมวด แยกฝั่งรายรับและรายจ่าย (หมวดที่ไม่มีรายการในเดือนนั้นไม่ต้องแสดง)
- ถ้าเดือนที่เลือกไม่มีรายการเลย ต้องแสดง empty state ไม่ใช่ยอด 0 ที่กำกวมหรือหน้าว่างเปล่า
- ตัวเลขเงินแสดงหน่วยบาท

## ข้อความบนหน้าจอที่ต้องตรงเป๊ะ (On-screen copy — ห้ามพิมพ์ต่างจากนี้)

- ป้ายยอดรายรับรวม: «รายรับรวม»
- ป้ายยอดรายจ่ายรวม: «รายจ่ายรวม»
- ป้ายยอดคงเหลือ: «คงเหลือ»
- ข้อความเมื่อเดือนที่เลือกไม่มีรายการ (empty state): «ไม่มีรายการในเดือนนี้»

## Acceptance Criteria

- [ ] เมื่อผู้ใช้เปิดหน้าสรุปยอดรายเดือน → ระบบแสดงตัวเลือกเดือน โดยค่าเริ่มต้นเป็นเดือนปัจจุบัน และแสดงป้าย «รายรับรวม», «รายจ่ายรวม», «คงเหลือ»
- [ ] เมื่อผู้ใช้เลือกเดือนที่มีรายการ → ระบบแสดงยอดใต้ป้าย «รายรับรวม» และ «รายจ่ายรวม» เท่ากับผลรวมของรายการประเภทนั้น ๆ เฉพาะในเดือนที่เลือก
- [ ] เมื่อระบบแสดงยอด «คงเหลือ» → ค่าต้องเท่ากับ (รายรับรวม − รายจ่ายรวม) ของเดือนที่เลือก
- [ ] เมื่อยอดรายจ่ายรวมมากกว่ายอดรายรับรวม → ยอด «คงเหลือ» ต้องแสดงเป็นค่าติดลบอย่างชัดเจน (มีเครื่องหมายลบ)
- [ ] เมื่อเดือนที่เลือกมีรายการหลายหมวด → ระบบแสดงยอดแยกตามหมวดหมู่ โดยยอดรวมของทุกหมวดฝั่งรายจ่ายต้องเท่ากับ «รายจ่ายรวม» และฝั่งรายรับเท่ากับ «รายรับรวม»
- [ ] เมื่อผู้ใช้เลือกเดือนที่ไม่มีรายการใด ๆ → ระบบแสดงข้อความ «ไม่มีรายการในเดือนนี้»
- [ ] เมื่อผู้ใช้เปลี่ยนจากเดือนที่มีรายการไปเดือนที่ไม่มีรายการ แล้วเปลี่ยนกลับ → ยอดสรุปต้องอัปเดตตามเดือนที่เลือกทุกครั้ง (ไม่ค้างค่าเดิม)

## Test steps (สำหรับผู้ทดสอบที่คลิกในเบราว์เซอร์ ไม่ต้องเป็นนักพัฒนา)

1. เตรียมข้อมูล: เพิ่มรายการในเดือน กรกฎาคม 2026 ดังนี้ — รายรับ "เงินเดือน" `20000`, รายจ่าย "อาหาร" `1500`, รายจ่าย "เดินทาง" `500`
2. เปิด URL ของระบบที่ deploy แล้วในเบราว์เซอร์ (Chrome) ไปที่หน้าสรุปยอดรายเดือน
3. ตรวจว่ามีตัวเลือกเดือน และเห็นป้าย «รายรับรวม», «รายจ่ายรวม», «คงเหลือ»
4. เลือกเดือน กรกฎาคม 2026 → ตรวจว่า «รายรับรวม» = 20000, «รายจ่ายรวม» = 2000, «คงเหลือ» = 18000
5. ตรวจส่วนแยกตามหมวดหมู่ → ต้องเห็น รายรับ: เงินเดือน 20000 / รายจ่าย: อาหาร 1500, เดินทาง 500 (รวมรายจ่าย 2000 ตรงกับ «รายจ่ายรวม»)
6. (ทดสอบยอดติดลบ) เพิ่มรายจ่าย "อาหาร" อีก `25000` ในเดือนเดียวกัน แล้วดูสรุปเดือนกรกฎาคม 2026 อีกครั้ง → «คงเหลือ» ต้องแสดงค่าติดลบ (มีเครื่องหมายลบ)
7. เปลี่ยนตัวเลือกเดือนไปเป็นเดือนที่ไม่มีรายการ เช่น มกราคม 2026 → ต้องเห็นข้อความ «ไม่มีรายการในเดือนนี้»
8. เปลี่ยนกลับมาเดือน กรกฎาคม 2026 → ตรวจว่ายอดสรุปกลับมาแสดงถูกต้องอีกครั้ง (ไม่ค้างค่าเดือนก่อนหน้า)
