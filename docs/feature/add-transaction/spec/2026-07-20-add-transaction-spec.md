# Spec: เพิ่มรายการรายรับ/รายจ่าย (add-transaction)

- **slug:** `add-transaction`
- **priority:** p1
- **วันที่:** 2026-07-20
- **ผู้เขียน:** BA/SA

## สรุปงาน (Summary)

ฟอร์มสำหรับเพิ่มรายการเงินหนึ่งรายการ ผู้ใช้กรอก จำนวนเงิน, ประเภท (รายรับ/รายจ่าย), หมวดหมู่, วันที่ และบันทึกช่วยจำ (ไม่บังคับ) เมื่อกดบันทึก ระบบตรวจความถูกต้อง แล้วเก็บลง `localStorage` คีย์ `tws.transactions` และแสดงรายการที่เพิ่งเพิ่มในรายการทันทีโดยไม่ต้องรีเฟรชหน้า เป็นฟีเจอร์รากฐานที่นิยาม schema ให้ฟีเจอร์ #2 (history) และ #3 (summary) ใช้ร่วม

## หมายเหตุ/ขอบเขต (Scope notes)

- เก็บข้อมูลใน `localStorage` คีย์เดียว `tws.transactions` เป็น JSON array; หนึ่งรายการมี field: `id` (string, อิงเวลา), `type` (`"income"` | `"expense"`), `amount` (number > 0, บาท), `category` (string), `date` (ISO `YYYY-MM-DD`), `note` (optional)
- `id` สร้างจากฝั่ง client อิง timestamp ให้ไม่ซ้ำ — ไม่มี server DB
- ขอบเขตนี้ครอบเฉพาะการ "เพิ่ม" และ "แสดงผลหลังเพิ่ม" — การดูย้อนหลัง/ลบ อยู่ที่ฟีเจอร์ `history-list`, การสรุปยอดอยู่ที่ `monthly-summary`
- ยังไม่รองรับการแก้ไขรายการเดิม (edit) ในเฟสนี้
- จำนวนเงินรับเฉพาะค่ามากกว่า 0; ถ้าใส่ 0, ติดลบ, หรือไม่ใช่ตัวเลข ถือว่าไม่ผ่าน
- ค่าเริ่มต้นของช่องวันที่ = วันที่ปัจจุบัน เพื่อลดการกรอกผิด

## ข้อความบนหน้าจอที่ต้องตรงเป๊ะ (On-screen copy — ห้ามพิมพ์ต่างจากนี้)

- ปุ่มบันทึก: «บันทึกรายการ»
- ข้อความเตือนเมื่อจำนวนเงินไม่ถูกต้อง: «กรุณากรอกจำนวนเงินให้มากกว่า 0»
- ข้อความเตือนเมื่อไม่เลือกหมวดหมู่: «กรุณาเลือกหมวดหมู่»
- ข้อความแจ้งบันทึกสำเร็จ: «บันทึกรายการเรียบร้อยแล้ว»

## Acceptance Criteria

- [ ] เมื่อผู้ใช้เปิดหน้าเพิ่มรายการ → ระบบแสดงฟอร์มที่มีช่อง จำนวนเงิน, ประเภท (รายรับ/รายจ่าย), หมวดหมู่, วันที่, บันทึกช่วยจำ และปุ่มที่มีข้อความ «บันทึกรายการ»
- [ ] เมื่อผู้ใช้กรอกครบทุกช่องที่บังคับ (จำนวนเงิน > 0, ประเภท, หมวดหมู่, วันที่) แล้วกด «บันทึกรายการ» → ระบบแสดงข้อความ «บันทึกรายการเรียบร้อยแล้ว» และรายการใหม่ปรากฏในรายการบนหน้าจอทันที
- [ ] เมื่อผู้ใช้กดปุ่ม «บันทึกรายการ» โดยเว้นช่องจำนวนเงินว่าง หรือกรอก 0 หรือค่าติดลบ → ระบบไม่บันทึก และแสดงข้อความ «กรุณากรอกจำนวนเงินให้มากกว่า 0»
- [ ] เมื่อผู้ใช้กดปุ่ม «บันทึกรายการ» โดยยังไม่เลือกหมวดหมู่ → ระบบไม่บันทึก และแสดงข้อความ «กรุณาเลือกหมวดหมู่»
- [ ] เมื่อผู้ใช้เลือกประเภทเป็น "รายจ่าย" แล้วบันทึกสำเร็จ → รายการที่แสดงระบุว่าเป็นรายจ่าย (แยกออกจากรายรับได้ชัดเจนด้วยข้อความหรือสี)
- [ ] เมื่อบันทึกรายการสำเร็จแล้วผู้ใช้กด Refresh (F5) หน้าเว็บ → รายการที่เพิ่งเพิ่มยังคงอยู่ (ยืนยันว่าถูกเขียนลง `localStorage` จริง)
- [ ] เมื่อบันทึกสำเร็จ → ช่องบันทึกช่วยจำที่เว้นว่างไว้ต้องไม่ทำให้บันทึกล้มเหลว (บันทึกช่วยจำเป็น optional)

## Test steps (สำหรับผู้ทดสอบที่คลิกในเบราว์เซอร์ ไม่ต้องเป็นนักพัฒนา)

1. เปิด URL ของระบบที่ deploy แล้วในเบราว์เซอร์ (Chrome)
2. ดูว่ามีฟอร์มพร้อมช่อง จำนวนเงิน, ประเภท, หมวดหมู่, วันที่, บันทึกช่วยจำ และปุ่มที่เขียนว่า «บันทึกรายการ»
3. กดปุ่ม «บันทึกรายการ» ทันทีโดยไม่กรอกจำนวนเงิน → ต้องเห็นข้อความ «กรุณากรอกจำนวนเงินให้มากกว่า 0»
4. กรอกจำนวนเงิน `0` แล้วกด «บันทึกรายการ» → ต้องเห็นข้อความ «กรุณากรอกจำนวนเงินให้มากกว่า 0» เหมือนเดิม (ไม่บันทึก)
5. กรอกจำนวนเงิน `120` เลือกประเภท "รายจ่าย" แต่ยังไม่เลือกหมวดหมู่ แล้วกด «บันทึกรายการ» → ต้องเห็นข้อความ «กรุณาเลือกหมวดหมู่»
6. เลือกหมวดหมู่ "อาหาร" ตรวจว่าช่องวันที่มีค่าอยู่แล้ว (วันนี้) เว้นช่องบันทึกช่วยจำว่างไว้ แล้วกด «บันทึกรายการ»
7. ต้องเห็นข้อความ «บันทึกรายการเรียบร้อยแล้ว» และเห็นรายการ "รายจ่าย / อาหาร / 120" โผล่ในรายการบนหน้าจอ
8. กด Refresh (F5) → ตรวจว่ารายการนั้นยังอยู่
9. เพิ่มอีกหนึ่งรายการเป็นประเภท "รายรับ" หมวด "เงินเดือน" จำนวน `20000` → ตรวจว่าแยกประเภทรายรับ/รายจ่ายได้ชัดเจนบนหน้าจอ
